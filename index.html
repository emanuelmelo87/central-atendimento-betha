💡 Dicas Gerais
📅 Quando o cliente questionar prazo de incidente, repasse o SLO do desenvolvimento. Se já estourado, informe que acionará o responsável e registre comentário público + interno ao gestor.
⏸ Ao sanar mais de uma dúvida na ligação, registre chamados distintos. Se precisar de tempo para registrá-los, coloque-se Em Pausa na fila para não receber novas ligações.
💬 Sem ligações? Continue os atendimentos registrados via Portal de Atendimento.
🧪 Utilize sempre ambientes de teste para simulação — nunca a base oficial do cliente.
🗣️ Se não souber a resposta, não diga "Sou novo" ou "Não sei". Diga: "Vou verificar e retorno em um ou dois minutos. Consegue aguardar?"
🔍 Para incidentes de instabilidade no Cloud/Fly, consulte status.betha.cloud e use como evidência.

🐛 Template — Incidente para o desenvolvimento ▼
*1 - Descrição*
Descrever brevemente a inconsistência relatada pelo cliente e se possível informar o impacto/bloqueio que a inconsistência está gerando ao cliente.

*2 - Cliente*
Entidade utilizada na simulação.

*3 - Funcionalidade*
Funcionalidade X

*4 - Versão do sistema*
Versão X.X.X

*5 - Base de dados*
Caminho na rede onde consta a base de dados, somente se necessário.

*6 - Token de conversão Cloud*
Disponibilizar o token de conversão Cloud, somente se necessário. (Token obrigatório para chamados de migração Cloud).

*7 - Acesso na entidade Cloud para o usuário*
Habilitar o parâmetro "Acesso técnico".

*8 - Passos para simulação e Evidências*

*8.1. Passos para simulação*
Informar os passos que foram utilizados no Ambiente de homologação/testes para constatar que o problema ocorre. Exemplo:
- Acessar a tela X;
- Campo X: Teste;

*8.2 Evidências*
A evidência é o que ocorre de fato no cliente. Informar como chegou à constatação de que a situação é uma inconsistência: Prints, consultas SQL's, logs do sistema (Ambiente de produção).

Quando conversão:
- Enviar o arqjoblet que está ocasionando o incidente;
- Informar os nomes e os registros das tabelas de migração com erros;
- Informar a consulta do arqjoblet que alimenta as tabelas de migração com a inconsistência.

*9 - Necessidade*
Relatar o que necessita ser ajustado. Para Incidentes que geraram erro em dados, informar também a necessidade de correção dos dados do cliente.

O cliente é transferido imediatamente. Você sai da ligação assim que o ramal atender.

Você pode falar com o colega antes de transferir e permanecer junto na ligação se precisar.
